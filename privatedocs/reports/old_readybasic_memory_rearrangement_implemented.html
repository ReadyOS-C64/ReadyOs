Current Baseline

ReadyBASIC now gives BASIC an empty workspace of 33789 bytes.

BASIC text starts at $1C01 variables start at $1C03 BASIC top is $A000 $A000 - $1C03 = 33789 bytes (33.0K)

Stock C64 BASIC V2 gives about 38911 bytes.

stock BASIC text starts at $0801 stock BASIC top is $A000 $A000 - $0801 = 38911 bytes (38.0K)
ReadyBASIC is now 5122 bytes (5.0K) below stock. Before this branch it had 26109 bytes (25.5K) free, so this branch reclaimed 7680 bytes (7.5K).

The 128 descriptors live in REU bank $44:$1000-$1FFF. Lookup fetches one 256-byte page into $C500, scans eight descriptors, and copies a match to $C480. SCRCAP is slot 13; SCRPUT is slot 128. Handle descriptors live at $44:$0800-$09FF, the heap bitmap lives at $44:$0C00, and the typed heap is $44:$4000-$FFFF / 48KB.

Loading-Only Or Rarely Needed Code

Code/data can be reused only if it is not needed while a BASIC program is stored in that address range. Load-only seed bytes are easy. Runtime parser, dispatch, and commit code must remain callable whenever BASIC dispatches a statement.

Proposed Rearrangement Stages

1

Move Frames

Move shared frames from $2400-$27FF to $C200-$C5FF.

2

Reclaim Load Range

Let BASIC start at $2401 after cold seed.

3

Bank Workers

Run command workers under BASIC ROM instead of the low overlay slot.

4

REU Resume

Move zero page and stack snapshots into REU; refresh helper shadow in visible RAM.

5

Raise Top

Move BASIC top from $9600 back to $A000.

+3072 bytes3.0K stage 1 frame move target: $9600 - $2403.
+5120 bytes5.0K stage 2 worker move target: $9600 - $1C03.
+7680 bytes7.5K stage 3 REU resume target: $A000 - $1C03.
The worker-under-ROM stage is the behavioral hinge: workers must not call BASIC ROM while BASIC ROM is banked out. Resident visible code should keep owning parsing and result commit.

The practical high-value target is 33789 bytes free. Getting beyond that requires moving or radically shrinking the visible resident core below $1C00, which is much riskier.

Command Growth Model

The REU registry remains the right scaling model.

Incremental Cost

0 BASIC workspace bytes usually 0 resident bytes 32-byte descriptor slot packed command code bytes

That is for a new command that reuses an existing parameter/result signature. A new signature may grow resident parser or commit code, but it still should not consume BASIC workspace.

Scaling Rules

  • Keep descriptors in REU and fetch them a page at a time.
  • Add more packed command-code banks when $45 fills.
  • Add a bank id or pack id to the descriptor format.
  • Keep shared parser/commit code resident only when several commands reuse it.
  • Store large command-private state in REU and expose BASIC integer handles.

Risks And Proofs Run

  • Prove hidden-worker-only execution for every current command, not just HCRC.
  • Prove no worker calls BASIC ROM while BASIC ROM is banked out.
  • Prove shared frames at $C200-$C5FF do not collide with bridge growth or ReadyOS metadata.
  • Prove EXIT can save runtime state to REU and warm entry can restore it before BASIC resumes.
  • Prove missing or corrupt REU state falls back safely.
  • Rebuild VICE probes for direct mode, stored programs, IF ... THEN !, strings/REM/DATA safety, arrays, handles, failures, EXIT, and cross-app resume.
The implementation stays within the ReadyOS app-window contract: it does not claim $C600-$C7FF, $C800-$C9FF, or ROM/I/O space as BASIC workspace.

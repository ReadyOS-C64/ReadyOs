# ReadyOS 0.5 RC2 integration and SKU audit

2026-10-30. Branch: `0.5-rc2`. Integration source commit: `74b91f0`;
reproducible archive/capacity tooling: `1c201e5`.

C64OS integration was already in RC2. The GDOS/GEOS work has now been committed
and fast-forwarded into RC2. Native C64OS Bridge Setup/patch/undo/installer source,
GDOS and GEOS return accessories, build/test tools and release binaries are all
checked in here. See [bridge source map](../../experiments/BRIDGES.md).
The sibling copies remain available but are not required for release builds.

## Rebuild and validation

The initial 17 disk profiles plus EasyFlash were rebuilt using
`/bin/bash ./run.sh --build-all --for-release`, version **0.5**, without a suffix.
The regular GEOS and D81 profiles were refreshed afterward to use identical,
reproducible CAR metadata and leave the default generated configuration at skip 0.

Passed: release directory ordering for all SKUs; packaged SEQ/REL byte audits;
REU schema-v5 and memory-map checks; EasyFlash release validation; expected
bridge inclusion for all disk profiles; companion CAR/CVT byte comparisons;
CAR CRC and native return-utility provenance. No unmanaged files were found in
any release disk image. Native GDOS/GEOS CVTs match the previously tested lab
binaries byte for byte. Native C64OS CPU-model tests passed all 25 bank caps,
undo, every single-byte corruption, invalid lengths/versions, commit/update and
failed-write rollback. The full build also runs its normal protocol/host checks.

The user reports manual hardware testing. This integration did not perform a
new physical round-trip regression. Historical VICE/hardware evidence remains
outside Git; it is not repackaged as a new verification run.

each free CBM block contributes 254 bytes of file payload. This is remaining disk
space, not REU space. Values do not include host-folder CAR/CVT companions, which
are outside the images. EasyFlash's extra figure is unallocated whole flash banks.

## What bundled bridges can actually do

- **Regular D81:** no bridge PRGs, manifests or native installer companions.
- **Stock Ultimate:** optional C64OS/GDOS PRGs and drive-9 manifests on disk 2;
  compiled skip0 disables switching. Native CAR/CVT installers ship beside the
  images. Enabled switching uses the corresponding dedicated SKU.
- **Regular GEOS experiment:** skip 71 enables the GEOS2 bridge with its matching
  native accessory and fixed memory contract. The inherited C64OS binary and
  CAR are also present, but C64OS switching is disabled because it requires skip 39.
- **Ultimate C64OS:** skip 39, full Ultimate app set, native setup/return CAR,
  and a complete setup guide; the bridge is first in the main catalog.
- **Ultimate GDOS/GEOS experiments:** skip 71, only the corresponding bridge app
  and native CVT. The stock Ultimate keeps skip0; its optional bridge copies are on disk 2.
- **Other normal/debug SKUs and EasyFlash:** no bridge apps or companions.

C64OS requires 1.09, the supplied reversible REU cap,16 MiB REU and compiled ReadyOS
skip 39. GDOS requires the supported 1.03 / 4 MiB DACC layout and skip 71. Stock GEOS2.0
uses its 512 KiB allocation with the conservative low 64-bank reservation and
skip 71. These are distinct fixed layouts; a dedicated C64OS
skip-39 release profile is now available, but there is no universal image
supporting all three bridge contracts.
Changing a disk catalog alone does not change the boot's compiled reservation.

## Decisions for final release

- Before the Read.Me revision, the regular D81 had 169 blocks / 41.9 KiB free after relocating its two bridge
  apps and optional manifest to stock Ultimate disk2. The native companions also
  moved to the Ultimate release folder; they never consumed D81 image space.
- Solo D64 C and E are the tightest normal disks: 3.5 KiB and 2.2 KiB free. The
  E debug disk has 2.0 KiB. They have little room for additional apps or user data.
- Before the Read.Me revision, the stock Ultimate boot disk had 33.5 KiB free; its examples/optional-apps disk has 719.8 KiB.
  Additional free space on disk 2 cannot satisfy boot-disk payload requirements.
- Suggested boundary: retain skip 0 stock SKUs and distribute ready-to-switch
  bridges as separate, explicitly configured experiments. The new dedicated skip-39
  Ultimate C64OS profile supplies that configuration without a custom rebuild.
  The optional C64OS/GDOS payload has now been relocated as requested.

## Repository scope

The integrated bridge sources and deliverable payloads are in RC2. Private OS
installations, runtime captures, local backups and worktree recovery records
are not release inputs.

The demonstration Site remains an intentionally separate sibling repository,
`../readyos-c64os-demo`, managed and versioned by Sites. Its media and hosting
configuration are not required to build these bridge releases.


## Follow-up: full Ultimate C64OS SKU

The requested `precog-ultimate-c64os` variant is now the 19th built SKU. It carries
all stock Ultimate apps/resources/examples, adds the C64OS bridge to the main
catalog, compiles skip39, and supplies the native CAR with checksum metadata.
At introduction its boot D81 had 74 free blocks and its examples disk had 3,026. The capacity table above reflects the subsequent Read.Me rebuild.
It uses the current0.5 release without a rolling suffix.

Each dedicated Ultimate bridge now carries a complete setup guide in README.md,
help.md and helpme.md, including native component installation, target OS device
and location setup, image/DMA path,16MiB requirement, fixed REU ownership,
return/resume, recovery and validation limits. Documentation-only refreshes now
preserve these guides. The stock Ultimate remains skip0; optional C64OS/GDOS copies on disk 2 refuse switching.
The new build/package checks do not claim a new physical round-trip test.


## Follow-up: bridge apps relocated to stock Ultimate disk 2

At the user's request the regular single-D81 SKU now excludes C64OS/GDOS PRGs,
app manifests and CAR/CVT companions. Stock Ultimate retains its main catalog
and skip-zero reservation, while disk2 carries `c64os`, `gdos64`, `app.c64os`
and `app.gdos64`. Both manifests select device 9 and appear first in the directory.
The native installers/checksum files accompany the Ultimate release images.

The dedicated Ultimate variants explicitly remove the optional drive-9 copies
from their inherited examples disk; their enabled bridge stays on disk 1. The
separate GEOS D81 variant retains its existing optional C64OS payload. Explicit
private C64OS/GDOS catalog overrides can still build their experimental regular
D81 labs; the stock regular catalog no longer packages those apps.

The build preservation list keeps both manifests build-owned after removal,
preventing old release images from restoring them as user data. Package checks
cover both image placement and manifest drive 9 bytes, along with complete
example retention and directory ordering. No switching transport changed.

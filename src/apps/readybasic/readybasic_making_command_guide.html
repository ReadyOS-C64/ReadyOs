ReadyBASIC Making Command Guide

A teaching guide for how current bare COMMAND(...) examples are wired into descriptors, parser signatures, under-ROM module payloads, overlays, and REU handles.

Current Module/Submodule Authoring Model

The detailed examples below are preserved because they explain parser signatures, frames, string staging, arrays, REU handles, and expression returns. The current placement model is now module/submodule based: descriptors identify the payload in the assigned code bank and the under-ROM slot or span where it must run.

Descriptor

32 bytes: command id, module id, payload offset/size, submodule, overlay, slot mask, generation, runtime destination, entry, signature, name.

Common

$A000-$A7FF is shared helper space, not a normal pageable command slot.

Slot 0

$A800-$AFFF is the default/system module slot for common commands.

Slot 1/2

$B000-$B7FF and $B800-$BFFF can hold swappable submodules, spans, and overlays.

Disk Modules

ZMODLD(name$) lives in module 2 and opens ReadyBasicModule SEQ packages named rbm.<name>. $C500 is only a streaming page buffer; descriptors land in the assigned core bank and payloads in the assigned code bank.

A module is the logical command family. A module package is the disk container. A submodule is the runtime payload family that claims a slot mask. An overlay is a replaceable payload image for the same submodule, so repeated submodule ids are normal when overlay ids differ.

Older references below to LOWPACK, HIDDENPACK, and LOW/HIDDEN flags remain as useful pre-module examples. For new commands, emit the module-aware descriptor fields and choose an explicit slot mask.

What You Are Building

A ReadyBASIC command is not just one assembler routine. It is a contract between BASIC text, resident parser code, a cold REU descriptor, and an overlay worker copied into C64 RAM only when needed.

Native PROC/FUNC routines, REPEAT/UNTIL, LABEL/JUMP, and ERRCODE/ERRLINE are ReadyBASIC language/runtime features, not plugin commands. Use this guide when adding new descriptor-backed command overlays.

Built-In And Module Command Growth

ReadyBASIC's built-in command set is intended to include the core commands and the 100+ additional file, graphics, sound, REU, and utility commands that are similar in spirit to other BASIC extensions. The current built-in code-bank reservations leave the contiguous tail $8000-$FFFF free for future built-in payloads; today's first C64 CMDPACK seed window has about $00AB / 171 bytes unused, while replacement overlays are seeded from CMDPACK2.

Beyond that built-in set, ReadyBASIC will also support dynamically loaded command modules that can use additional REU banks, so other authors can add hundreds more commands without forcing everything into the core command bank.

1. User Types

ZADD16(4,5,A%) is visible BASIC text. The command name must survive C64 tokenization.

2. Lookup

ReadyBASIC pages descriptor records from the assigned core bank and finds the matching command name.

3. Parse

The descriptor's signature id selects resident parser code, which fills CF_* call-frame fields.

4. Execute

The descriptor tells ReadyBASIC which packed code bytes to copy from the assigned code bank and where to call them.

5. Commit

The worker writes RF_* result-frame fields. Resident code commits the result to BASIC only on success.

When To Use PROC/FUNC Instead

Use a native ReadyBASIC routine when reusable logic is naturally program code that a user should be able to create in their own program.

1000 PROC DRAW(P%,N$)
1010    PRINT P%;N$
1020 ENDP

1100 FUNC ADDI(X%,Y%)
1110    R%=X%+Y%
1120    RET R%
1130 ENDP

10 EXEC DRAW(3,"PLAYER")
20 A%=ADDI(4,5)
30 PRINT ADDI(6,7)

PROC has input formals only. FUNC also declares input formals only and returns with RET expr; use RET% expr or RET$ expr when the return type should be explicit. FUNC is called as an expression and does not take a final output actual. V1 supports % integer, $ string, and plain C64 BASIC float formals; arrays, locals, by-reference parameters, and multiple outputs remain out of scope. Definitions should live after END; fall-through into a definition is invalid.

Use a descriptor-backed command overlay when the routine needs hidden RAM, REU handles, fast machine-code loops, direct screen/color memory, or shared command behavior.

Use resident language work when the feature changes BASIC control flow or interpreter state. REPEAT/UNTIL stores and restores TXTPTR/CURLIN; LABEL/JUMP scans stored BASIC lines; ERRCODE/ERRLINE returns resident runtime state.

SID Sound Command Tutorial

Sound Phase 1 commands are descriptor-backed module 4 commands in the SIDCORE slot-2 replacement overlay. The overlay is prestashed at code-bank offset $7800 and runs at $B800-$BA0D.

The packed VOICE form was chosen deliberately. A seven-argument parser shape was tested but grew resident code; the implemented form reuses an existing numeric signature and keeps BASIC free bytes unchanged.

MCELL writes the three per-cell multicolor bitmap attributes: screen high nibble, screen low nibble, and color RAM. MCBG sets the shared background color.

Multicolor bitmap colors are per 8x8 cell. A later slot-1, slot-2, or slot-3 write in the same cell can recolor earlier pixels that used that same slot.

Naming Rules

ReadyBASIC names are visible BASIC text, not private tokens. New command names must avoid substrings that C64 BASIC can tokenize inside the command name, including CLR, FRE, NOT, INT, FN, LEN, OR, and TO. Host .bas demos should spell ReadyBASIC commands lowercase so petcat writes ordinary PETSCII letters.

This alpha build registers no duplicate public command spellings. ReadyBASIC can implement an alias by adding another 32-byte descriptor that points at the same command id, signature, payload, and entrypoint, but that spends a registry slot, expands QA/documentation surface, and can preserve tokenizer hazards. Current demos and tests must use the canonical names only.

Z*Example, demo, and proof commands.
X*Alpha/beta commands whose behavior or parameter shape is not settled yet.
U*Commodore 64 Ultimate / Ultimate Family specific commands.
XU*Alpha/beta Ultimate-specific commands whose behavior or parameter shape is not settled yet.

Current public names include ZECHO1, ZADD16, UPPER, LOWER, ZHIDDENRAM, ZSUMNUMARRAY, ZRANGENUMARRAY, BUFMAKE, BUFFILL, BUFDROP, SCRCAP, SCRPUT, ZTEMPSCRATCH, ZPAUSE, ZFAIL, MEMAVL, ERRCODE, ERRLINE, ZSLOT0, ZSLOT1, ZSLOT2, ZSPAN, ZOVL1, ZOVL2, ZCPYRST, ZCOPY, and ZMODLD. Disk-module samples add ZDM1, ZDM2S, ZDOV1, ZDOV2, and ZSAA-ZUEB after loading RBM.SAMPLE1, RBM.SAMPLE2, or RBM.SAMPLE3.

Descriptor Shape

Descriptors are cold-seeded into assigned core-bank offsets $1000-$1FFF. Runtime lookup fetches one 256-byte page, scans eight descriptors, then copies the match to RB_DESC_BUF.

.macro CMD_LOW id, sig, label, endlabel, name
        .byte id, RB_MODULE_SYSTEM
        .word 0                       ; payload offset in assigned code bank
        .word __LOWPACK_SIZE__        ; slot-0 payload size
        .byte RB_SUBMOD_LEGACY_LOW
        .byte 0                       ; overlay id
        .byte RB_SLOT_LEGACY_LOW      ; slot mask: $A800
        .byte 1                       ; generation/check byte
        .word 0                       ; runtime destination offset from $A000
        .word label - __LOWPACK_RUN__ ; entry offset
        .byte sig, .strlen(name)
        .byte name
        .res 16 - .strlen(name), 0
.endmacro
.macro CMD_LOW_ALL id, sig, label, name
        .byte id, RB_MODULE_SYSTEM
        .word 0                    ; whole slot-0 payload
        .word __LOWPACK_SIZE__
        .byte RB_SUBMOD_LEGACY_LOW
        .byte 0
        .byte RB_SLOT_LEGACY_LOW
        .byte 1
        .word 0
        .word label - __LOWPACK_RUN__
        .byte sig, .strlen(name)
        .byte name
        .res 16 - .strlen(name), 0
.endmacro

.macro CMD_SLOT1 id, sig, label, name
        .byte id, 2
        .word __SLOTPACK1_LOAD__ - __LOWPACK_LOAD__
        .word __SLOTPACK1_SIZE__
        .byte RB_SUBMOD_PROOF_SLOT1
        .byte 0
        .byte RB_SLOT_PROOF_1
        .byte 1
        .word 0
        .word label - __SLOTPACK1_RUN__
        .byte sig, .strlen(name)
        .byte name
        .res 16 - .strlen(name), 0
.endmacro
Descriptor fieldWhat it teaches
idInternal command id. It is stable command identity, separate from the command's slot number.
sigParser signature id. This is how lookup chooses which resident parser routine fills the call frame.
label / endlabelAssembler labels that define the worker entry and, for slice-copy commands, the exact number of bytes to copy.
module/submodule/overlayIdentifies which module payload or overlay must be resident before the entry is called.
slot maskBit 0 selects $A800, bit 1 selects $B000, and bit 2 selects $B800.
CMD_LOW_ALLUsed when a tiny command wrapper calls shared helpers elsewhere in the slot-0 payload, so the whole slot-0 payload must be available.

Small Commands

ZECHO1

resident precomputescalar int

Minimum scalar-command skeleton: statement form captures OUT%, expression form has no output actual, and resident code stages integer 1 without fetching an overlay.

10 ZECHO1(P%)

20 PRINT "ZECHO";P%

30 PRINT "EXPR";ZECHO1()

        jsr rb_parse_out_int_current
        jmp rb_precompute_zecho1

rb_precompute_zecho1:
        lda #0
        sta RF_STATUS
        lda #RB_VAL_INT
        sta RF_TAG
        lda #1
        sta RF_VAL_LO
        lda #0
        sta RF_VAL_HI
        lda #1
        sta rb_command_precomputed
        rts
CMD_LOW_ALL CMD_ZECHO1, SIG_ZECHO1,
        cmd_zecho1_low, "ZECHO1"

String Commands

UPPER and LOWER share parse_sig_string_out. The overlay transforms bytes into RF_STR_BUF; resident code owns BASIC string heap allocation.

10 UPPER("ready",T$)
20 PRINT T$

30 L$=LOWER("LOUD")
40 PRINT ASC(L$);ASC(MID$(L$,2,1));ASC(MID$(L$,3,1));ASC(MID$(L$,4,1))

50 PRINT LEFT$(UPPER("ready"),2)
parse_sig_string_out:
        jsr rb_parse_string_value
        jsr rb_parse_out_string
        rts

cmd_lower_low:
        lda #0
        sta RF_STATUS
        lda #RB_VAL_STRING
        sta RF_TAG
        lda CF_STR_LEN
        sta RF_STR_LEN
        ldy #0
@loop:
        cpy CF_STR_LEN
        beq @done
        lda CF_STR_BUF,y
        cmp #'A'
        bcc :+
        cmp #'Z' + 1
        bcs :+
        clc
        adc #$20
:       sta RF_STR_BUF,y
        iny
        jmp @loop
@done:
        rts
CMD_LOW CMD_UPPER, SIG_UPPER,
        cmd_upper_low, cmd_upper_low_end, "UPPER"
CMD_LOW CMD_LOWER, SIG_LOWER,
        cmd_lower_low, cmd_lower_low_end, "LOWER"
Line or groupTeaching note
parse_sig_string_out:Shared parser shape for commands that take one string value and one output string variable.
rb_parse_string_valueAccepts a string expression or literal and stages the bytes in CF_STR_BUF.
rb_parse_out_stringCaptures the destination string variable. BASIC string heap mutation is still resident-code work.
RF_STR_LEN = CF_STR_LENCopies the input length because case conversion preserves length.
@loop / cpy CF_STR_LENWalks the staged string one byte at a time using Y as the index.
cmp #'A' ... adc #$20Converts ordinary ASCII uppercase bytes to lowercase bytes.
sta RF_STR_BUF,yWrites transformed bytes to the result frame, not directly to BASIC string memory.
CMD_LOW ... "UPPER"/"LOWER"Two public commands share the same parser shape but point at different byte-transform workers.

The source also handles shifted C64 letter bytes. Tests assert ASC() values because visual case depends on the active C64 charset.

rb_handle_allocFinds a free handle id, reserves heap pages in REU, writes canonical metadata, and stages the handle number as an integer result.
rb_handle_fillValidates that the handle is a generic buffer before writing data. This is where type safety lives.
rb_handle_freeAccepts any valid typed handle and releases both descriptor metadata and heap pages.
rb_screen_handle_allocAllocates a type-2 screen text+color handle, sized for the screen snapshot resource.
lda RF_STATUS / beq :+Stops immediately if allocation or validation failed, preserving the error status for resident code.
rb_screen_save_text/colorCopies text RAM and color RAM into the typed REU handle.
rb_screen_load_text/colorRestores text RAM and color RAM only after the handle type has been validated.
CMD_LOW_ALL ...These commands call shared helpers, so the descriptor copies the whole slot-0 payload instead of just the wrapper bytes.

The handle lesson is to keep BASIC-visible values small, keep canonical resource metadata in REU, and validate handle type at command boundaries. BUFFILL accepts only type-1 buffer handles; SCRPUT accepts only type-2 screen text+color handles; BUFDROP frees any valid type.

Naming Lessons And Add-Command Checklist

  1. Choose a tokenizer-safe name.
  2. Add command id and signature id.
  3. Add or reuse a parser signature that fills the call frame and clears outputs.
  4. Add a low or hidden worker that writes the result frame only on success.
  5. Add a descriptor entry; use CMD_LOW_ALL only when shared helpers require the full slot-0 payload.
  6. Keep resident growth minimal; prefer REU metadata and existing scratch pages.
  7. Update the descriptor filler count so real descriptors plus filler still fit exactly in RB_CMD_DESC_COUNT.
  8. Add direct, stored-program, error-path, and resume/slot coverage.
  9. Update Markdown and HTML docs with measured map values after tests pass.

Current Expression-Style Behavior

Current ReadyBASIC supports two related styles: command statements that write to an output actual, and expression-safe calls that return a value directly into BASIC's expression evaluator.

Statement Output

The final argument is the output target. Resident code clears it before the worker runs and commits only after success.

10 ZADD16(4,5,A%)
20 PRINT "SUM";A%

30 UPPER("ready",T$)
40 PRINT T$

50 BUFMAKE(64,H%)
60 PRINT "HANDLE";H%

Expression Return

The call returns a scalar or string value directly. It can be assigned, printed, or passed into another expression consumer.

10 A%=ZADD16(4,5)
20 PRINT "SUM";A%

30 PRINT ZADD16(5,10)
40 T$=UPPER("ready")

50 H%=BUFMAKE(64)
60 PRINT "HANDLE";H%

Formal Parameters

PROC and FUNC definitions name the values their body expects. These are ReadyBASIC routine formals, not plugin descriptor signatures.

100 PROC SHOWI(P%)
110    PRINT "PROCI";P%
120 ENDP

200 FUNC ADDI(X%,Y%)
210    RET X%+Y%
220 ENDP

Actual Parameters

Calls provide actual values. Non-empty argument lists use parentheses for both EXEC and FUNC calls.

10 EXEC SHOWI(7)

20 PRINT ADDI(1,2+4)
30 PRINT ADDI(1,(2+4))
40 PRINT ADDI((1+2),(3+4))

Commands with array outputs or no scalar result remain statement-only. For example, ZRANGENUMARRAY(7,4,R%(0)) writes several array elements after success, so it is not an expression return. Scalar handle commands such as BUFMAKE(n) and SCRCAP() are expression-enabled because the returned handle is a simple integer.

True Expression Examples

Inputs and returned outputs can both participate in larger expressions, mixing ReadyBASIC commands, ReadyBASIC FUNC routines, and built-in BASIC functions.

Expression Inputs

Actual parameters can come from built-in BASIC expressions, ReadyBASIC command returns, or other ReadyBASIC FUNC returns.

10 PRINT ADDI(ABS(-2),ZADD16(2,3))

20 PRINT ZADD16(1,ADDI(2,3))

30 PRINT FADD(1.5,FADD(2.25,3.25))

Expression Outputs

Returned values can feed built-in BASIC functions or larger string/numeric expressions.

10 PRINT ABS(ZADD16(1,6)-10)

20 PRINT ABS(ADDI(1,6)-10)

30 T$=LEFT$(GREET("READY")+"!",3)
40 PRINT T$

50 PRINT LEFT$(UPPER(GREET("ready")),2)

FUNC Return Markers

FUNC routines return through RET expr. Use RET% expr or RET$ expr when the return type should be explicit.

100 FUNC GREET(N$)
110    RET "HI "+N$
120 ENDP

200 FUNC IDI(X%)
210    RET% X%
220 ENDP

300 FUNC IDS(S$)
310    RET$ S$
320 ENDP
